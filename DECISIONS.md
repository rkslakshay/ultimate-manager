# Decisions

Significant technical and design decisions, newest last. Each entry: context → decision →
consequences. Deviations from `CLAUDE.md` are marked **[deviation]**.

## 2026-10-14 — Phase 0

### D-001 npm workspaces instead of pnpm [deviation: minor]

CLAUDE.md allows npm or pnpm. pnpm isn't installed on the dev machine; npm 11 workspaces cover
our needs. Internal packages (`@um/shared`, `@um/engine`) export **TypeScript source** via
`exports` → no build step or watch process in dev; Vite and tsx compile them on the fly.

### D-002 PostgreSQL everywhere, with an embedded server for local dev [deviation: additive]

Docker is not available on the dev machine, and SQLite would mean maintaining two Prisma
providers/migration sets. Instead `npm run dev` starts a real PostgreSQL 18 via the
`embedded-postgres` npm package (binaries ship as per-platform npm packages; data in
`.data/postgres`, port 5433). `DB_MODE=external` uses Docker Compose (also mapped to 5433) or any
other server; CI uses a Postgres service container. One provider, one migration history.
Risk: `embedded-postgres` is only published with beta tags; it's pinned exactly
(`18.3.0-beta.17`) and only used for development/tests, never production.

### D-003 TypeScript 6.0, not 7.0 [deviation: version]

TS 7 (the native port) is `latest`, but `typescript-eslint` supports `<6.1`. We use TS ~6.0.3
with `strict`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`. Revisit when typed linting
supports TS 7. TS 6 deprecates `baseUrl`, so path aliases are relative (`./src/*`).

### D-004 Prisma 7 with the `pg` driver adapter

Prisma 7 is current stable (8.0 is RC). It requires `prisma.config.ts` (URL no longer in the
schema) and a driver adapter (`@prisma/adapter-pg`). The client is generated to
`apps/api/src/generated/prisma` (gitignored; generated by `npm run dev`, CI and tests).

### D-005 REST + Fastify 5 (not tRPC)

Plain REST with Zod schemas from `@um/shared` validating inputs on the server and forms on the
client. Easier to test with `app.inject`, to document, and to call from scripts. Uniform error
body `{ error: { code, message, fieldErrors? } }`; codes are a shared enum.

### D-006 Auth: JWT in an httpOnly cookie, backed by a Session table

- JWT (HS256, `@fastify/jwt`) carries `{ sub: userId, sid: sessionId }`, stored in an
  `httpOnly`, `SameSite=Lax`, `Secure`-in-production cookie. No token in JS-readable storage.
- Every authenticated request checks the `Session` row, so **logout and future "sign out
  everywhere"/password change can revoke tokens**. Costs one indexed lookup per request.
- CSRF: `SameSite=Lax` blocks cross-site POSTs carrying the cookie; the API only accepts JSON.
- `bcryptjs` (pure JS) instead of native `bcrypt` to avoid node-gyp builds on Windows. Cost 12 in
  dev/prod, 4 in tests. Login does a dummy compare for unknown emails (no user enumeration by
  timing) and returns the same message for both failure modes.
- Auth routes are rate-limited per IP (`RATE_LIMIT_AUTH_MAX`/minute).

### D-007 Save games: max 10 per user; seed-driven worlds

Each save stores a `seed` (user-provided or random 64-bit hex). The whole world will be generated
and simulated deterministically from it (Phase 1+). Careers start on 2026-07-01 (pre-season).
Other users' saves always return 404 (not 403) to avoid revealing existence.

### D-008 Front end stack details

React 19, Vite 8, Tailwind CSS v4 (CSS-first `@theme` tokens), **React Router 7** and
**TanStack Table 8** pinned to majors with well-known APIs (newer majors exist). shadcn/ui-style
components are written by hand on the unified `radix-ui` package rather than via the shadcn
CLI (non-interactive environment; same result: owned source in `components/ui`). Server state
in TanStack Query, client UI state in Zustand (persisted sidebar state). Toasts via `sonner`.
Recharts and Framer Motion will be added when first needed (Phase 4).

### D-009 Design system: dense dark theme, 13px base

See `docs/DESIGN_SYSTEM.md`. Single dark theme (the spec calls for dark); tokens are CSS
variables so a light theme could be added later. Violet accent (`#6b5be6`) chosen to avoid
real clubs' colours. A 5-step 1–20 attribute colour ramp is defined up front. Every text/background
pair was checked to meet WCAG AA (4.5:1); this forced separate tokens for _solid fills_ (`accent`,
`danger-solid`, white text) versus _coloured text_ on dark surfaces (`accent-text`, `danger`),
and darker (not lighter) hover states on filled buttons.

### D-010 Seeded RNG: SFC32 + cyrb128/splitmix32 seeding

32-bit integer arithmetic only → bit-identical in Node and browsers. Full state is 4×uint32 and
serialisable; `normal()` deliberately discards the Box-Muller pair so `getState()` is exact.
`fork(label)` derives independent sub-streams (per match, per subsystem) while advancing the
parent by exactly one step. A pinned reference sequence test guards against accidental
algorithm changes (bump `ENGINE_VERSION` if it must change). ESLint forbids `Math.random`,
`Date`, `process`, DOM globals and Node/React/Prisma imports inside the engine.

### D-011 npm `allowScripts` allow-list

npm 11 blocks dependency install scripts by default. `package.json#allowScripts` allows exactly:
`prisma`, `@prisma/engines` (engine download), `@embedded-postgres/*` (binary symlinks on
macOS/Linux) and `esbuild` (binary check). Note this overrides any user-level `allow-scripts`.

### D-012 Dev orchestration in a small Node script, not `concurrently`

`scripts/dev.mjs` must sequence DB start → migrate → generate → servers, and stop the embedded
database cleanly on Ctrl+C. A ~100-line script does this with prefixed output and no extra
dependency. Processes are spawned via `node` directly (no shell) to avoid Node's DEP0190.

## 2026-10-14 — Phase 1

### D-013 World storage: per-save tables, composite keys, no cross-table FKs

Every world table is keyed by `(saveId, id)` where `id` is the engine's small integer id, with
`ON DELETE CASCADE` from `SaveGame`. There are deliberately no foreign keys _between_ world
tables: the engine guarantees integrity, and FK-free tables make the bulk writes of the season
loop (Phase 3) simple and fast. Attributes/hidden/positions are `int[]` columns (compact, still
queryable with `attributes[i]`); searchable fields (CA, value, position, club, name) get indexes.

### D-014 Bulk inserts via `jsonb_to_recordset`

Prisma `createMany` binds ~27 parameters per player and took 1.2-2.9 s per world. One
`INSERT … SELECT FROM jsonb_to_recordset($json)` per batch takes ~230 ms. Postgres converts
JSON arrays to `int[]` natively. The same technique will serve the Phase 3 diff flush.

### D-015 Current Ability is derived, not rolled

CA is a pure function of attributes and primary position (per-position weights → weighted
1-20 score → 1-200). Generation targets a CA and nudges attributes until they match, and any
edit or (later) development recomputes CA. This keeps CA, ratings and attributes consistent.
Stars = CA/40 (absolute), a simplification of FM's squad-relative stars.

### D-016 Names: common first names, generated surnames and places

Given names come from common per-style lists; surnames, towns and clubs are built from
morphemes, so full names are invented combinations. 8 naming styles cover 9 fictional nations.

### D-017 The engine has no `Date`

Game dates are integer day numbers with Hinnant's civil-date algorithms (exhaustively tested
1800-2200). This removes host time-zone effects from simulation; ISO strings only at the edges.

### D-018 UTF-8 everywhere for Postgres

initdb on Windows inherits the system code page (WIN1252 here), which cannot store many
generated names. Clusters are initialised `--encoding=UTF8 --locale=C`, databases are always
created `ENCODING 'UTF8' TEMPLATE template0`, test DBs with another encoding are recreated, and
dev DBs are converted with all rows copied and the original kept as a backup database.

### D-019 Abilities visible until scouting exists

Until Phase 6 adds knowledge levels, star ratings show real CA/PA and the editor shows exact
numbers. Player search filters by primary position only; matching every playable position
needs an array-index query or a denormalised column (revisit with the transfer market).
